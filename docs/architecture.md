# معماری سامانهٔ پیشنهاد مبلمان

## اصل طراحی

موتور پیشنهاددهی یک تابع قطعی و مستقل از Django، دیتابیس و مدل زبانی است. نقش و نوع محصول فیلتر قطعی هستند؛ ظرفیت، بودجه، سبک و رنگ طبق منطق نسخهٔ اولیه امتیاز ایجاد می‌کنند. مرتب‌سازی با امتیاز نزولی و سپس فاصلهٔ قیمت صعودی انجام می‌شود.

## جریان درخواست

1. کلاینت دادهٔ ساخت‌یافته را به API می‌فرستد.
2. Serializer ساختار و سازگاری بودجه را بررسی می‌کند.
3. سرویس فقط محصولات فعال با نقش و نوع مربوط را از دیتابیس می‌گیرد.
4. مدل‌های ORM به مدل دامنه تبدیل و به موتور اصلی ارسال می‌شوند.
5. پنج نتیجهٔ برتر همراه امتیاز و فاصلهٔ قیمت ذخیره می‌شوند.
6. API نتیجه و شناسهٔ عمومی درخواست را برمی‌گرداند.

مدل زبانی در تصمیم‌گیری دخالت ندارد. در فاز رابط گفتگو، وظیفهٔ آن فقط تبدیل متن فارسی به ورودی ساخت‌یافتهٔ همین API خواهد بود.

## مرز ماژول‌ها

- `recommendation/recommend`: قواعد خالص و قابل تست
- `apps/products`: کاتالوگ و پنل مدیریت
- `apps/recommendations`: API، orchestration، تاریخچه و بازخورد
- `recommendation/agents`: رابط قدیمی CLI و اتصال اختیاری AvalAI
- `config`: تنظیمات و ورودی‌های Django

## مقیاس‌پذیری فعلی

فیلتر نقش و نوع محصول در خود QuerySet انجام می‌شود و فقط نامزدهای مرتبط وارد موتور می‌شوند. نتایج با `bulk_create` ذخیره می‌شوند و فهرست تاریخچه با `prefetch_related` بارگیری می‌شود. Redis، Celery یا microservice تا زمانی که اندازه‌گیری بار نیازشان را ثابت نکند وارد معماری نمی‌شوند.
